01FISHINGLOG / REST API
JAVA · SPRING BOOT · POSTGRESQL

A fishing log,
built to last.

FishingLog is a REST API for storing and exploring fish records, with separate controller, service, and repository layers.

  • Create, read, update, and delete fish records.
  • Search by species and lake, count records, and retrieve the top-K fish by weight.
  • Persist records in PostgreSQL through Spring Data JPA, with database-generated IDs.

I tested endpoints in Postman and moved the database password out of the source code. Unit tests for updateFish() check that changed fields are saved, the updated fish is returned, and a missing ID produces an error. The current tests work, with more coverage still to be written.

UNDER THE HOOD

From request to record.

FishingLog separates HTTP requests, application logic, and database access. Explore each layer below.

01 / CONTROLLERHandle the request

The controller exposes the REST endpoints and passes requests to the service layer.

02 / SERVICEApply the logic

The service handles application behavior, including updating fish records, and works with the repository.

03 / REPOSITORYAccess the data

Spring Data JPA connects repository operations to persistence, with Hibernate handling the object-to-database mapping.

04 / POSTGRESQLKeep the record

PostgreSQL stores fish records between application runs and generates record IDs.

THE MOTIVATION

A project I’d use myself.

I started FishingLog to learn Spring by building something connected to my own interest in fishing. Logging catches gave me a practical place to start. The longer-term idea is to help anglers connect and share locations, highlights, and stories.

THE CHALLENGE

Understanding the pieces.

The hardest part was learning how Spring’s layers fit together, and how JPA and Hibernate relate to database persistence. Unit tests were especially challenging as I worked through Mockito and how to test the application’s behavior. The current tests work, and expanding coverage is an ongoing part of the project.

THE LEARNING

Beyond the endpoints.

The project pushed me to think about the responsibilities of each layer, persistence, and testing. SQL was another language to learn—and one of the parts I most enjoyed exploring.

THE DIRECTION

From a log to a community.

The current project is a REST API for fish records. Connecting anglers and sharing fishing stories is the vision for where I’d like to take it next.
